路线 3：服务 + MCP + Web 控制台，拆成三版

目标是先把本地常驻服务跑稳，再让 AI 和人共用同一个控制面。

总体架构方向
CLI
service start
service stop
service status
service logs
Web Console
runs list
run detail
render
cleanup preview
MCP Tools
get status
list runs
start scan
render run
all call into
Service Core
scheduler, recording source scanner, copy/stage, job runner, state store, event log, run lifecycle
V1

常驻服务内核

CLI 自管进程。支持 start / stop / status / logs；读取配置录播源；定时扫描 NAS；复制到 input；启动 pipeline；检测 selected_clips 后自动 render；清理只预演。

V2

MCP 工具面

AI 不再拼 shell 命令，而是通过 MCP 调服务能力：查询服务状态、列 run、看 run 详情、触发扫描、读取审阅包、写选择、触发渲染、预演清理。

V3

统一控制台

Web 控制台改为服务客户端。人和 AI 看到同一套 run 状态、事件、动作权限和错误信息；后续再考虑 launchd / 开机自启 / 多录播源增强。

推荐第一版边界

先实现 V1，但代码边界按 V3 预留：把调度、状态、动作封成 Service Core，让 CLI、Web、MCP 后续只是不同入口。
