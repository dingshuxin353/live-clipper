# StarWork 项目工作台

类型：项目工作台

适合具体项目执行层。默认形态是独立项目工作台；如果由项目中心通过 `spawn` 创建，CLI 会额外叠加项目中心同步说明。

## 包含

- 默认中文路径 profile
- 本地身份和教训模板
- 项目事实源和当前工作入口
- Kit 自带 skill 挂载能力

## 规则

项目工作台是具体项目执行层。独立项目本地维护身份和教训；知识库是可选能力，需要长期沉淀项目知识时再开启。由项目中心创建的管理关系由 `starwork spawn` 额外生成，不是项目工作台的默认可见结构。

本 kit 预期包含：

- `_系统/上下文/当前项目.md`：项目状态事实源
- `_系统/任务/当前工作.md`：当前工作入口
- `_系统/身份/`：项目本地长期背景和偏好模板
- `_系统/教训/`：项目本地可复用经验模板
- `.agents/skills/`、`.claude/skills/`：按需挂载项目可用 skill

具体业务目录由 Pack 或用户定制目录决定。默认的 General Pack 会生成 `参考资料/`、`输出/草稿/` 和 `输出/确认成果/`；它们不是 Project Kit 的基础结构。

如果用户需要让 AI 长期整理项目知识，运行 `starwork knowledge init` 开启 `知识库/` 能力。

## 不默认包含

- `参考资料/`
- `输出/`
- `事项/`
- `_系统/上下文/决策.md`
- `_系统/主库同步/`
- `.core-sync.json`
- `.internal/`

项目特定事实进入项目自己的正式事实源，不写回项目中心正式目录。

`_系统/上下文/当前项目.md` 是项目状态事实源。不要同时维护另一份 `_系统/上下文/项目状态.md`。

注意：`.starwork/`、`.obsidian/` 是隐藏路径，很多文件管理器默认看不到。独立项目用户日常先关注 `AGENTS.md`、`_系统/` 和已安装 Pack 创建的业务目录。
